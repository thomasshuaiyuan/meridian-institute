Delay-NPE · illustrative

Pay once, then infer for free.

Fitting a delay-aware model separately to every surveillance unit does not scale. One national centre, one week, one sampler run — multiply by a hundred and fifty centres and fifty-two weeks and the arithmetic stops working, which is what keeps delay-aware inference a per-study exercise rather than a running system.

Amortised inference moves the cost. Simulate from the model once, train an estimator that maps data straight to a posterior, and every dataset afterwards is a forward pass. The expense is paid up front and never again.

Where the trained estimator is entitled to answer

The failure mode is not slowness, it is confidence. A sampler run on a dataset the model fits badly tends to show it — poor mixing, wide intervals, divergences. An amortised estimator asked about data outside its training distribution returns a posterior just as quickly and just as narrowly as for any other input, and that posterior can be wrong. The rose points are datasets outside the simulated support; nothing in the forward pass flags them, so the check has to be built, not assumed.

This is the design decision behind Delay-NPE, which cleared its design gate on 3 November 2026 and is blocked before Phase 0 on a definition rather than on compute: what the bins are indexed by. Fitting a prior on one axis for a target on another is the grid-mismatch failure that already cost one run, and it is cheaper to settle in a sentence than in a simulation.
